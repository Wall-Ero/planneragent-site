## Durable admission and stopping

Before creating the Teacher attempt, the runner validates exact configuration,
frozen payload and existing exposure admission. It creates `claim.json` with
exclusive `wx`, writes it and calls fsync before proceeding. The fixed experiment
ID is not configurable. Concurrent calls sharing the directory cannot both claim.
An existing/partial claim, existing result, I/O error or missing configuration
fails closed. A crash after claim consumes the experiment permanently, even when
no result was written. Results are written exclusively and fsynced as `result.json`.

The marker remains after every outcome: valid, malformed, free prose, provider
failure, timeout or unknown usage. No refund, fallback, automatic continuation or
second attempt exists. The quota fixture has `max_retries:0`; the transport has
one fixture. A local unavailable Student fixture triggers the existing supervisor;
no Student model/service is contacted or reactivated.

This is a per-directory, single-machine admission journal on a trusted local
filesystem supporting exclusive creation and fsync. It is not a distributed
lock, tamper-proof store, cross-directory/account-wide quota or guarantee against
manual deletion/rollback or power-loss filesystem failures. It is not a second
operational ledger. STEP 13G D1 accounting remains DESIGN_READY and DEFERRED.

Realization parser, existing source-bound independent verifier, supervisor and
`OfflineHybridEvidenceRegistryV1`. Its validated content-free observations are
persisted with the local report; no candidate plaintext is added to the registry.

The report separates envelope validity, full checked structural conformity,
semantic gate status, linguistic review and synthetic usage. Envelope validity

INCONCLUSIVE. PASS is limited to the existing whole-answer source-bound renderer
scope; linguistic quality always requires independent review. Public response is
the deterministic baseline and never replaced by the Teacher. Evidence remains
SHADOW/PENDING_ELIGIBILITY; there is no automatic training or TRAIN export.

Real requests and real Neurons are zero. Fixture input/output tokens and Neurons
are synthetic, including unknown-metering scenarios. The internal 4,096-token
fixture limit is NOT a qualified bound on live prompt/template tokens. No token
conversion is a live Neuron receipt. Free billing enforcement is an external cap,
not application authorization or proof of available daily quota.

## Future credential boundary and open live prerequisites

Only a non-secret contract is implemented. No token argument, environment loader,
secret file reader or credential fallback exists. `inspectFutureLivePrerequisitesV1`
accepts only assertions, never a token, and always returns live execution disabled.
Missing dedicated-credential evidence blocks future readiness, while DRY_RUN
deliberately requires no real secret. No Lightning, Student, OpenRouter or Wrangler
OAuth credential can be used through this runner.

For future review, scope a dedicated token to the one verified account and Workers
AI only. The [official REST guide](https://developers.cloudflare.com/workers-ai/get-started/rest-api/)
specifies Workers AI Read and Edit. The [endpoint reference](https://developers.cloudflare.com/api/resources/ai/methods/run/)
lists Read or Write; the exact least privilege must be rechecked before provisioning.
No Worker/D1/DNS/billing permissions are justified by this experiment.

Future live use requires manual confirmation of Workers Free, dashboard usage and
remaining daily allocation, dedicated credential scope, explicit operator
authorization, qualified input/token bound, one request, no retry/upgrade/Gateway
payment and definitive stopping after every outcome. A separate reviewed live
executor/transport and an honest treatment of live token usage/unknown Neurons
are still missing. This adapter cannot ingest actual Neurons via `offline_neurons`.
No live transport or new authorization is implemented in 13H.

Single next step: independently review the live-only transport/credential/input
bound specification and manual admission checklist. Do not invoke inference.
